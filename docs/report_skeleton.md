# Report Skeleton

## Project Description

This project implements a ROS 2 Humble robotic sorting cell. A Panda robot plans to pick a QR-labeled workpiece, move it to a scan station, decode the QR content using `zbar_ros`, map the decoded content to a bin, and place the object in the selected bin.

## System Architecture

Packages:

- `qr_sorting_bringup`: launch and YAML parameters.
- `qr_sorting_logic`: QR image simulation, decision logic, and visualization markers.
- `qr_sorting_mtc`: MoveIt Task Constructor manipulation task.

Core topics:

- `/qr_sort/sim_camera/image_raw`
- `/barcode`
- `/qr_sort/bin_id`
- `/qr_sort/bin_pose`
- `/qr_sort/scan_ready`
- `/qr_sort/visualization`
- `/solution`

## Motion Planning Pipeline

The robot model is the Panda from `moveit_resources_panda_moveit_config`. The project uses MoveIt Task Constructor stages for ready motion, gripper open/close, approach, lift, scan, bin placement, release, retreat, and home return.

The workpiece is inserted as a MoveIt collision object named `workpiece`. A small collision object named `pick_station_support` represents the fixed station in the MoveIt planning scene. During grasp, contact between the hand links and the workpiece is allowed, the Panda fingers close to a configured width around the exterior of the 6 cm cube, and a grasp-center IK offset keeps the palm/finger base outside the cube. `ModifyPlanningScene::attachObject` then attaches the object to `panda_hand`.

The bins are modeled twice: as readable RViz open-top container markers and as MoveIt collision objects made from a floor plus four walls. The place phase moves above the selected bin opening, lowers vertically into the bin, opens the gripper, detaches the workpiece, retreats upward, returns home, and restores collision checking.

## QR Perception Pipeline

The simulated camera generates a QR image using the configured `qr_text`. It waits for the MTC scan trigger before publishing. `zbar_ros` decodes the image and publishes `/barcode`. `qr_decision_node` maps decoded text to the configured bin pose.

## Challenges And Solutions

- Header mismatch: Humble uses `moveit/planning_scene_interface/planning_scene_interface.h`.
- Object carry behavior: added a real collision object plus attach/detach MTC stages.
- Scan timing: added `/qr_sort/scan_ready` so QR images are published only after the pick-to-scan solution reaches the scan stage.
- Release collision: collision checking is restored after retreat/home so the hand can release while still close to the cube.
- Environment collision: a full-size table collision object blocked Panda ready/pick states, so the planning scene now uses a smaller pick-station support collision object while the larger workcell remains a visual marker.
- RViz readability: reduced large overlapping text labels, moved bins into a clean row, rendered bins as square open-top containers, hid the static pick marker after the scan trigger, and added compact camera/frustum, QR panel, route, and status markers.
- Gripper realism: replaced the fully closed Panda hand state with configurable finger-width targets and a grasp-frame offset so the clamp visually holds the outside of the object.
- Bin collision realism: added MoveIt collision boxes for bin floors/walls and changed placement to a top-down approach, lower, release, and retreat sequence.

## Evidence Checklist

- Clean colcon build succeeds.
- `/qr_sort/scan_ready` is published after pick-to-scan planning.
- `zbar_ros` decodes the generated QR image to `/barcode`.
- `qr_decision_node` publishes `/qr_sort/bin_id` and `/qr_sort/bin_pose`.
- MTC full task reports one solution.
- RViz shows robot, workpiece, scanner, bins, selected bin, and MTC task tree.
- Workcell markers are readable and do not obscure the Panda robot.
- BIN_A, BIN_B, BIN_C, and UNKNOWN were smoke-tested with the final collision-aware bin layout.

## Limitations

- The project currently uses RViz/MoveIt simulation, not Gazebo physics.
- The QR image is generated by a simulated camera node.
- The scan trigger is planning-based, not a physical camera event.
- Execution is disabled by default; animation/inspection through RViz Motion Planning Tasks is the primary demo path.
